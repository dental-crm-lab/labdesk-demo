# MedLab

Доска заказов, приём заявок от врачей и финансовый учёт для CAD-CAM зуботехнической лаборатории — белый лейбл (нейтральный бренд «MedLab», легко переименовать под конкретного клиента).

Это демо-версия основного продукта: тот же код и функциональность, но с пустой базой — ни сотрудников (кроме одного демо-логина), ни врачей, ни заказов. Годится и для показа новым клиентам, и как шаблон для разворачивания нового отдельного инстанса под конкретную лабораторию.

Самостоятельный веб-сервис (не зависит от Claude) — свой бэкенд, своя база, реальная загрузка файлов сканов, работает как обычный сайт, PWA и десктоп-приложение (Windows).

## Что внутри

- `server/` — бэкенд (Node.js + Express + Socket.IO): хранит данные в `server/data/db.json`, файлы сканов — в `server/data/uploads/`, отдаёт живые обновления через WebSocket. Плюс push-уведомления (новый заказ / срок сдачи / просрочка — настраивается по ролям в Настройках) и отдельная супер-админ панель для мониторинга (`/superadmin`, логин/пароль — переменные окружения `SUPERADMIN_LOGIN` / `SUPERADMIN_PASSWORD`).
- `public/` — фронтенд: одна страница `index.html` + PWA-манифест и иконки.
- `electron/` — десктопная обёртка (Windows .exe): тонкий клиент, который просто открывает адрес вашего сервера в отдельном окне.

## 1. Развернуть на Railway (через GitHub)

**Шаг 1 — залить код на GitHub.** Создайте пустой репозиторий на GitHub заранее («New repository», можно приватный), затем в папке проекта:

```bash
git init
git add .
git commit -m "MedLab demo"
git branch -M main
git remote add origin https://github.com/<ваш-аккаунт>/<имя-репозитория>.git
git push -u origin main
```

**Шаг 2 — Railway.**
1. Зайдите на [railway.app](https://railway.app), войдите через GitHub.
2. «New Project» → «Deploy from GitHub repo» → выберите ваш репозиторий.
3. Railway сам определит Node.js-проект и запустит `npm install && npm start`.
4. **Важно — постоянное хранилище.** Без него база и файлы будут исчезать при каждом передеплое. В настройках сервиса откройте вкладку **Volumes** → «New Volume» → точка монтирования `/data`. Затем во вкладке **Variables** добавьте переменную `DATA_DIR` со значением `/data`.
5. Там же, во вкладке **Variables**, задайте `PORT` = `3000` (иначе можно словить 502 — сгенерированный Railway домен ждёт именно этот порт).
6. Во вкладке **Settings → Networking** нажмите «Generate Domain» — получите публичный адрес вида `<название-проекта>-production.up.railway.app`.

Готово — сайт публичный, доступен по ссылке, без ограничений по аккаунтам.

## 2. PWA (устанавливается как приложение из браузера)

Ничего дополнительно делать не нужно — как только сайт развёрнут на Railway:
- **Компьютер (Chrome/Edge):** в адресной строке появится значок установки.
- **Android:** меню браузера → «Добавить на главный экран».
- **iPhone (Safari):** «Поделиться» → «На экран «Домой»».

## 3. Десктоп-приложение для Windows (.exe)

Готовые .exe весят ~75 МБ каждый, собираются одним из двух способов:

**Способ А — GitHub Actions (проще всего).** В репозитории уже есть `.github/workflows/build-windows.yml`. После того как код запушен на GitHub:
1. На GitHub → вкладка **Actions** → workflow «Build Windows app» → **Run workflow**.
2. Через 2-3 минуты в результатах появится вложение **MedLab-Windows** — скачайте и распакуйте, внутри оба .exe.

**Способ Б — собрать локально** (на Windows, либо на Linux/macOS с `wine`):

```bash
cd electron
npm install
npm run dist:win
```

Файлы появятся в `electron/dist/`: **`MedLab Setup 1.0.0.exe`** (установщик) и **`MedLab 1.0.0.exe`** (portable).

При первом запуске приложение попросит **адрес сервера** — вставьте туда домен из Railway (шаг 1.6). Дальше приложение просто открывает ваш сайт в отдельном окне. Если адрес сервера изменится — его можно поменять через меню **MedLab → Сменить адрес сервера…**, пересобирать .exe не нужно.

Чтобы приложение сразу открывало нужный сайт без экрана настройки — впишите домен в `electron/main.js` (`DEFAULT_SERVER_URL`) до сборки .exe.

## 4. Локальный запуск для разработки

```bash
npm install
npm start
```

Откройте `http://localhost:3000`. База данных создаётся автоматически в `server/data/`.

## Вход в приложение

- **Сотрудник:** «Я сотрудник лаборатории» → «Демо» → PIN `1234`. Это единственный предустановленный аккаунт (роль «Владелец») — переименуйте его и смените PIN в разделе «Сотрудники», добавьте реальных сотрудников там же.
- **Врач:** «Я врач / клиника» → номер телефона (при первом входе — имя и клиника). Открытая ссылка — любой врач может зайти сам.
- В «Настройках» есть кнопка **«Сбросить демо»** — одним нажатием чистит все заказы, врачей, оплаты, расходы, отгулы и историю изменений (сотрудники и настройки не трогает). Удобно после тестового показа — перед следующим клиентом.

## Как настроить под конкретного клиента

Ничего в коде менять не нужно — всё через интерфейс:
- «Настройки» → «Название лаборатории» — меняет название, которое показывается в шапке и на экране входа.
- «Этапы производства», «Сроки выполнения», «Нерабочие дни», «Оплата технику/фрезеровщику», «Push-уведомления» — под процессы конкретной лаборатории.
- «Прайс-лист» — свои позиции и цены.
- «Сотрудники» — реальные сотрудники вместо демо-логина.

Если нужен полностью отдельный инстанс под каждого клиента (своя база, свой Railway-проект, свой домен) — проще всего каждый раз брать этот репозиторий за основу (или сделать `git clone` в новую папку и завести отдельный GitHub-репозиторий + Railway-проект по шагам выше).

## Загрузка файлов сканов

Drag-and-drop или выбор файла, до 150 МБ на файл — сохраняются на сервере в `server/data/uploads/`. Поле для ссылки (Google Диск и т.п.) тоже есть — как запасной вариант.

## Технические детали

- Данные хранятся в одном JSON-файле (`server/data/db.json`) — этого более чем достаточно для объёма одной лаборатории.
- Живые обновления доски между устройствами — через Socket.IO, без перезагрузки страницы.
- Push-уведомления (новый заказ / срок сдачи сегодня-завтра / просрочка) работают на телефоне и в PWA через Web Push — ключи сервер генерирует сам при первом запуске, ничего вручную настраивать не нужно. На Electron-приложении уведомления приходят только пока оно открыто (это ограничение Electron, не баг).
- PIN-вход — простая защита внутри лаборатории, не полноценная авторизация с ролями/паролями.
